## 使用

环境已安装在 Conda 的 `supermimic` 环境，`behaviour` 环境不参与本工程。
重建环境使用 `bash scripts/bootstrap.sh`：普通包走阿里云镜像，特殊 CUDA wheel
使用固定来源；可用 `SUPERMIMIC_PYPI_INDEX` 指定其他 PyPI 镜像。
依赖版本、原始版本差异和数据来源见 [configs/README.md](configs/README.md)。

```bash
conda activate supermimic
python scripts/check_gpu.py

# 核对配置与源码锁，不创建 GPU 环境
python scripts/train_strict.py --robot g1 --mode config \
  --motion-dir data/npz/lafan1 --clips walk1_subject1 --run-name my_g1_config

# 完整原始规模容量检查：4096 环境，保留所有默认训练参数；只做首轮更新
python scripts/train_strict.py --robot g1 --mode probe \
  --motion-dir data/npz/lafan1 --clips walk1_subject1 --run-name my_g1_capacity

# T800 配置：更换本体与参考动作，保留上游算法和训练参数
python scripts/train_strict.py --robot t800 --mode config \
  --motion-dir data/npz/t800_single --clips walk2_steady --run-name my_t800_config
```

`--mode train` 调用原有 `Trainer.run()`，先确认机器能容纳原配置。
入口不会因显存不足自动减小网络、批量或想象长度；每次运行用新的 `run-name`。
`--resume` 会拒绝恢复使用不同训练配方的检查点。配置与来源记录写入 `reports/strict/<run-name>/`。
旧的 `scripts/run_experiment.py` 保留为明确标记的诊断工具，不再作为默认训练入口。

16 GiB 显存优化入口为 `scripts/train_memory.py`，支持完整或选择性激活重计算。
本轮使用 `optimizations/selective_recompute.py` 的 `--recompute-mode policy`，仅重算策略前向。
G1 仍加载未修改上游源码，T800 仍加载已审计适配源码。策略更新函数直接继承上游版本，
只改变策略前向与想象单步的中间激活保存方式，反向时重新计算。
原来的严格入口和两棵源码树保留；显存优化检查点会单独标记，严格入口拒绝将它们
当作未修改执行路径的续训检查点。

```bash
# 保留原始 4096 环境、完整 batch 4096 和 32 步反向，使用激活重计算。
# 先完成 8 次完整更新并保存；停止条件不改变原始 320k 步学习率规划。
python scripts/train_memory.py --robot g1 \
  --motion-dir data/npz/lafan1 --clips walk1_subject1 \
  --run-name my_g1_memory --stop-after-updates 8

# 新进程恢复并再执行 8 次更新，恢复前校验模型和优化器状态内容。
python scripts/train_memory.py --robot g1 \
  --motion-dir data/npz/lafan1 --clips walk1_subject1 \
  --run-name my_g1_memory_resume --stop-after-updates 8 \
  --resume logs/my_g1_memory/ckpt_latest.pt
```

`--stop-after-updates 0` 才会运行到原始训练总步数。有效 batch、网络、H、critic 配方、
噪声、域随机化和精度不提供缩小开关，也不改变原始 batch 的计算形状。
每次运行的配置、源码哈希、逐轮指标和显存记录见 `reports/microbatch/<run-name>/`。
恢复遵循原有流程：回放重新填充 40 步，不恢复 RNG/仿真状态；不声称与未中断训练逐步一致。

运行通用上游入口时，先设置 `SUPERMIMIC_ROBOT=t800`；未设置时保持 G1。
`--robot` 是上述实验脚本的参数，它会在导入模型前完成选择。
T800 检查点不能在 G1 进程中加载。G1 公开检查点不需要重新训练。

本地三维动作检查页面：

```bash
conda run --no-capture-output -n supermimic python scripts/view_motions.py
# 浏览器打开 http://127.0.0.1:8080/
```

参考与本轮实际策略轨迹同步对比：

```bash
conda run --no-capture-output -n supermimic python scripts/view_tracking.py
# 浏览器打开 http://127.0.0.1:8081/
```

蓝色为参考、橙色为实际记录。默认最终 2,000 次更新，可切换 1,984 / 1,484 次更新。
支持并排、同坐标叠加、路线显示、暂停和逐帧。并排显示的平移不参与误差计算。
评估目标帧比保存的状态帧编号提前一帧（20 ms）；页面用保存的逐帧误差验证这一映射，
与原评估指标保持一致。没有修改训练或评估源码，也没有平滑、对齐或修正实际运动。

默认显示训练使用的行走参考；下拉菜单可切换其他参考、合成站立和已保存的
策略/PD 物理记录。支持暂停、逐帧、慢放、视角切换及碰撞几何显示。
页面按记录设置姿态并计算运动学，不运行策略或物理积分；参考姿态显示流畅
不能证明动力学可实现。循环会直接跳回首帧。服务只监听本机，页面控制由访问者共享。

## 验证内容

- 原始算法保留在 `vendor/supermimic_upstream`；G1 仿真、公开检查点、短训练和恢复
  使用该目录的未修改代码验证。公开检查点在本次 299 帧短片段上完成回放，归一化回报 0.921；这不是论文完整基准。
- T800 的 25 个关节按名字映射，参数表在 `configs/t800-joints.json`。
  MJCF 来自固定版本的众擎 GMR，与固定版本 SDK XML 一致；控制参数来自众擎 RL Lab。
- `scripts/audit_motion.py` 检查限位、足底高度和可微 FK 的位置、旋转、速度及梯度。
  舞蹈示例和三个短 LAFAN1 片段的检查结果保存在 `reports/*motion-audit.json`。
- `scripts/evaluate_tracking.py` 记录根位置误差、关节 RMSE、动作进度、终止原因、
  关节限位、力矩饱和，以及世界模型 1–8 步误差。参考轨迹通过检查不代表策略学会动作。

世界模型的 NSE 是按上游状态尺度归一化后的均方误差，没有米或弧度单位。
评估默认从片段起点运行一次；`completed_clip` 表示是否整条完成，
`completion_fraction` 是走到片段的比例，不能解读为多次实验的成功率。
力矩/限位诊断在每个 50 Hz 控制步的最后一个物理子步采样，包含终止步。
训练日志还包含随机相位启动的 episode return，不能直接作为整条动作完成率。

T800 适配未启用众擎任务的随机 1–3 个物理步执行器延迟；额定速度
仅记录而没有硬裁剪。历史诊断使用额外 9 维锚点观测和缩小网络；严格配置已恢复
上游 `anchor_obs=False` 和原网络，并开启原有观测噪声、重置噪声和域随机化。
本工程尚不涉及真机部署。

## 历史缩小配置试训结果

固定的初始策略评估转移样本上，世界模型单步 NSE 从 0.588 降到 0.082，
8 步 NSE 从 12.069 降到 0.589。训练后的策略在新轨迹上的误差不同，
单步 / 8 步 NSE 分别为 0.132 / 1.122，具体数据均保留在评估 JSON 中。

最终一次确定性评估没有完成整条动作（0/1），到达片段长度的 26.3%；
平均根位置误差 0.199 m、关节位置 RMSE 0.407 rad、归一化回报 0.118。
硬限位越界和软限位超出分别占所采样关节状态的 6.62% 和 9.08%；
在所采样控制步末端未检测到力矩饱和。不能由此推断每个物理子步都没有饱和。
这些结果没有表现出有效的策略学习，后续需要定位动态控制与策略优化问题。

`scripts/reference_pd_probe.py` 还测试了直接输入参考关节角及加入速度前馈的
两个物理控制对照；两者都在约 0.8 秒终止。该对照不是学习策略，也不能据此
判定参考动作在动力学上绝对不可实现。

进一步用官方默认关节姿态生成了 6 秒双脚支撑的合成站立参考
（`scripts/make_standing_diagnostic.py`，不属于动作捕捉数据）。固定姿态 PD 对照
在 1.38 秒触发高度终止，保存轨迹显示机器人逐渐向前倾倒。
编译后的场景碰撞掩码允许足地接触，保存轨迹的 CPU 接触检查也检测到了足地接触；
这排除了掩码完全关闭足地碰撞的情况，但没有验证 GPU 接触力精度。
详见 `reports/t800-standing-pd.json` 和 `reports/t800-standing-contact-inspection.json`。
固定关节 PD 不等于主动平衡控制，当前证据尚不能确定是控制适配还是策略优化导致失败。

## 控制与站立学习对照（2026-10-27）

`scripts/audit_control_chain.py` 对 G1/T800 分别测试了逐关节动作映射、带噪声执行、
默认姿态偏置、实际 GPU PD 力矩、力矩限幅和回放中的干净/执行动作分离。
完整 10 帧观测历史及未来参考、锚点目标也与物理环境输入一致。
这些检查没有验证所有接触力细节或参考动作的动力学可实现性。

回放每行存的是当前动作对应的下一状态终止标签，采样时却取了下一行的标签，
导致倒数第二个动作也被提前标为终止。该问题来自上游快照，曾在诊断代码中修正；
独立回归样例修正前失败、修正后通过。现已为严格对齐恢复上游版本，回归样例标记
为明确说明原因的 `xfail(strict=True)`，不把这个已知问题记为测试通过。

随后用两种机器人的默认姿态分别生成 6 秒合成站立参考。四组实验均启用标签修正，
使用种子 0、128 个并行环境、2,000 个控制步、相同隐藏层规模、32 步策略想象、
8 步世界模型拟合和额外锚点观测；同一本体内仅切换 critic 末端价值估计。
两种本体的姿态、动力学和输入维度不同；同种子也不保证不同分支消耗随机数的顺序相同。

| 本体 | 初始策略 | 训练后，保留 critic | 训练后，关闭 critic |
| --- | ---: | ---: | ---: |
| G1 | 1.36 s | 0.14 s | 2.04 s |
| T800 | 1.38 s | 1.44 s | 1.78 s |

表中是每个检查点一次确定性评估的终止时间，所有策略都未完成 6 秒参考。
关闭 critic 后两者存活略有增加，但归一化回报仍低于初始策略，不能算已经学会站立。
G1 保留 critic 的实验从记录的第 800 步开始出现非有限策略梯度范数，并发生严重发散；
这将排查重点转向当前小规模配置下的共同优化稳定性，不能据此认定 critic 在所有配置下都不适用。

固定初始策略轨迹上的 T800 无 critic 世界模型 NSE：8 步约 0.010，32 步约 0.655。
短期预测误差低不保证长时间模型内轨迹可靠；这些是固定动作开环预测，不能替代闭环梯度验证。
局部动作扰动检查保存在 `reports/t800-walk-model-response.json`，只覆盖少量采样窗口。

四组实验之后，为 actor、critic、世界模型加入了非有限梯度范数报错检查，阻止该次异常
优化器更新；100 步 T800 短训练确认正常更新可以继续。该检查用于暴露数值异常，并非收敛修复。
`--no-critic` 和 `--anchor-obs` 是 `scripts/run_experiment.py` 的诊断开关；
`scripts/evaluate_tracking.py --wm-horizon 32` 可检查与策略想象同长度的模型预测。
上述标签修正及梯度检查现归档于 `patches/diagnostic-replay-label-and-grad-guard.patch`，
主路径不应用该补丁。世界模型额外预训练、渐增想象长度、关闭 critic 都是算法实验，
当前严格复现阶段不采用。

## 16 GiB 显存优化与一致性验证

最初采用**完整激活重计算**：策略和想象单步在反向时重算中间激活。
当前 T800 基线经性能及数值对照后，只重算策略前向，保留想象单步的激活；
原始 `PolicyTrainer.update` 直接继承，不改变 4096 batch 的形状或原有 Adam 步数。
使用非重入 checkpoint 并保留 RNG 状态；FP32、4096 环境、回放容量 1000、H=32、
原网络、critic、噪声、随机化和学习率保持不变。没有使用 AMP 或世界模型额外预训练。
环境初始化与上游一样调用 mjlab 默认后端设置，允许 TF32；float32 张量不意味着矩阵乘法禁用 TF32。
此前训练实际使用 TF32，而早期数值对照没有显式启用 TF32；补充的 TF32 对照未通过原门槛。
当前入口支持显式 `--matmul-precision ieee|tf32`，在环境初始化后设置并记录实际精度，
评估从检查点读取同一设置；恢复拒绝静默切换精度或重计算方式。
CPU eager 模式的 TorchScript 四元数函数不能透传重算提前停止异常，故该模式重算完整单步；
默认 CUDA 编译路径保持重计算默认的提前停止行为。

最初也实现了 512 分块梯度累积，代码保存在 `optimizations/policy_trainer.py` 和
`optimizations/rollout.py`。真实运动学下的 CPU float64 对照达到约 1e-15 的非日志误差；
但 CUDA 编译测试中，公开权重配新 Adam 状态的两轮更新，部分参数张量的差异达到
原版更新量的约 6.3%，未达到验收标准。因此分块版**不作为训练入口的默认实现**。
旧的逐元素容差失败和进一步诊断均保留于 `reports/microbatch/g1-cuda-*.json`。

`scripts/validate_microbatch.py --implementation recompute` 对比实际上游训练器与重计算版，
检查真实 FK/奖励、完整 32 步反向、GAE、随机数消耗、两轮 actor 更新、40 次 critic 更新、
模型与优化器状态。CUDA 对照使用能同时运行原版的 batch 1024，保留原网络并加载公开权重；
这不是对 batch 4096 整批原版的直接数值验证，也不是长期收敛等价性证明。

FP32 检查以完整梯度相对 L2 误差 ≤ 0.1%，以及每个参数张量的差异相对原版实际更新量
≤ 0.1% 为门槛，并保留最大绝对误差。最终重计算版还同时通过最初的逐元素容差
（FP32 atol 5e-6、rtol 5e-4；仅上游本来就用 float32 累加的奖励日志另记精度）。
分块方案的逐元素检查失败记录没有删除。CPU float64 保留逐元素检查。
重计算 CUDA 两轮对照通过，梯度最大相对 L2 误差 0.00242%，参数差异相对原版更新量
最大为 0.01798%；数值误差仍非零，因此不宣称逐位一致。
详见 [最终数值对照](reports/microbatch/g1-recompute-final-strict-parity.json)。

执行记录分别位于 `reports/microbatch/g1_memory_verified/` 与
`reports/microbatch/g1_memory_verified_resume/`。保存的检查点带有 `activation_recompute`
标记及源码哈希；模型和优化器状态在恢复后、继续更新前进行逐字节内容哈希核对。
